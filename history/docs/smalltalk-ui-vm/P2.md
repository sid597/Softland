  `:portal/composition` section. Other master rooms remain generic; there is no
  anatomy branch in `matter_room.cljc`.

### W6 — edit to one candidate through the existing hands

- The anatomy grammar now accepts exactly seven edit operations:
  `add`, `remove`, `reorder`, `retune-props`, `rebind-slot`,
  `attach-def`, and `detach-def`.
- An edit composes one whole candidate form client-side and validates that
  whole form before it can reach an append.
- Malformed edits return a teaching refusal with the offending path, actual
  value, and legal vocabulary. They do not alter latest, active, or pointer
  state.
- Successive edits use the current candidate as their basis. The live agent
  receipt combined a root `wrap-col` retune with all four invocation parts;
  neither edit overwrote the other.
- Human Workshop actions and `__portal.workshop` delegate to the same
  controller. Durable transitions reuse the existing
  preview → deviate → activate → rollback lanes.
- Activation ends the preview membrane before the pointer moves. Both
  activation and reversal re-open the served portal before trusting source or
  recovery data, so neither can operate through a stale projection.

### W7 — pressure triple

#### Paste clamp

- `fm:foldable` keeps its earlier grammar revisions byte-stable and gains
  grammar 3 with:

  ```edn

   {:threshold-chars 1200
    :max-share 0.5
    :header-copy "pasted"}}
  ```

- The one policy consult occurs only when `handle-content-key!` receives
  `:paste`. It reads the focused subject's worn foldable policy, or the current
  shared wear while birthing, and supplies that data to the existing edit
  machine.
- The durable block text retains the source mark, clamp metadata, and every
  pasted byte. Projection may show only the material fraction. The ordinary
  `fold/toggle-section` binding expands and collapses it; no paste verb or
  endpoint was added.

#### `fm:invocation`

- New grammar-0 `fm:invocation` carries:

  ```edn
  {:invocation/model "sonnet"
   :invocation/effort "low"
   :invocation/precontext "thread+2"}
  ```

- Model is a nonblank CLI value. Effort is closed to
  `low`, `medium`, `high`, `xhigh`, and `max`. Precontext is closed to
  `thread+0` through `thread+8`.
- The P2 anatomy candidate adds four visible parts: a heading plus the worn
  model, effort, and precontext. An instance deviation therefore changes only
  the addressed block's displayed and spawned settings.
- The server reads the source block's actual shared+instance invocation wear
  at `run-episode-turn`. Read failure fails closed to the invocation code
  floor rather than pretending the source had no setting.
- Precontext widens only the existing narrowed portal prompt and is bounded by
  its closed depth. It does not create a second context path.
- Model and effort thread into the existing `summon-argv` function. The argv
  builder omits absent values; it contains no model value literal.
- The actual spawn seam now prints its complete turn-start receipt directly to
  stdout. The isolated dev classpath's `log/info` provider was silent, which
  made the promised live receipt unobservable even though the turn completed.
  The narrow repair changed only the emission of the already-constructed
  receipt.
