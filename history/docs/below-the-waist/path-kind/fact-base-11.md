## Part 2 — derivations

- **The alive set is decidable from the program's text.** Steps run in order; `next` reads after them; `return` after that; a state field `next` never rebinds is carried across iterations. So the last read of every binding is known before the run starts (`compileUses`), and a paint whose input surface has no later read, with no other still-read binding holding the same object, may advance it in place. The pickup's `state.surface` is read at step 0 (sample) and step 2 (paint) and rebound by `next`: consumable at step 2. The proofs' `state.base` is never rebound: alive throughout, never consumed, and frozen anyway.
- **Why the identity has to be the step, not the depth.** Two branches from one parent are both one paint deep; a counter that measures depth cannot tell them apart, and an external cache keyed on `{ id, revision }` would return the wrong image. `<surface id>:<iteration>/<step>` is unique within a run because steps are straight-line; across runs a cache adds the run. The parent is kept beside it, not encoded in it.
- **Why the checkpoint is taken per host.** A checkpoint saved from one host and resumed on another carries that host's pixels into the other's continuation, so the comparison against the other host's straight run measures the two hosts' own differences, not the checkpoint. Taking it on each host from its own prefix isolates the checkpoint (0 differing components on both), and the cross-host number is then reported as what it is.
- **Why the mask needs the composite's coordinate frame.** The layer composite reads the layer at the fragment's own pixel (`gl_FragCoord`) and the mask at the fragment's local position; the mask's curves are in local units, so the composite draw's quad must be the view in local units under the camera map. Session 10 drew it in device units with an identity map, where a clip would have read local curves against device coordinates.
- **The rasterizer snap.** The vertex shader passes the local position as a varying; the rasterizer snaps vertex positions to its sub-pixel grid before interpolating; a varying interpolated from snapped corners is off by the snap scaled by the triangle's local-per-pixel ratio. At zoom 3 that is about 0.01 local; a clip edge through a pixel centre then reads 0.48 instead of 0.50; over the 128 × 128 pickup surface at one texel per local unit the same error spread across every dab edge as the 5.8e-3 the two hosts disagreed by. `gl_FragCoord` is exact per fragment; the inverse map is a uniform.

## Part 7 — the cost of republishing, measured this session (for Sid's question)

Republishing an existing artifact at the same URL requires the tool to have read the live version in full first, through the Read tool, regardless of the size of the edit. This session that was the bench (161 KB, four reads) and the page (128 KB, four reads), both byte-identical to the committed files, so nothing was merged and the reads bought nothing but the right to publish. A new URL would skip the read and break every link. The faster ways are: republish once per session at the end, both artifacts together (done here); or read the twin from the repo and republish the page only when its picture changes, since the definer works from the committed files and their hashes, not from the URLs.
