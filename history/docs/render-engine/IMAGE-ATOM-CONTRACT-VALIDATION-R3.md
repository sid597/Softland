**Claim under test.** §5: *"**Legacy direct-present regime (declared passthrough):** sRGB-tagged sources pass through in presentation-encoded space — a declared **ZERO-transfer row** (the regime's own declaration makes it lawful, **Contract C §8.2.5 shape**)…"*; G6: *"LEGACY direct-present: the declared zero-transfer passthrough row + the no-double-transfer sentinel."*

Zero is the one count §8.2.5 names as unlawful. The contract cites this sentence as the thing that *makes* the row lawful.
2. **Contract C's C4 receipt demands the equivalence the contract declines.** `W1.md:711-713`: *"**C4 transfer:** tagged sRGB solids/gradients and profiled test images are equivalent across direct present, intermediate present, readback, and export; exactly-one-transfer sentinels catch double/missing conversion."* §5's *"inter-regime divergence is a RECORDED known difference… never silently equated"* is the negation of C4's own predicate. ### N2 · FAIL — the image lane's order law is undeclared, and at the one collision the code permits it resolves through `stable-tie`, which W1 §3.1 forbids

**Claim under test.** §7: *"the registered image producer mints `[:frame/store vi :images]` batch entries… with the slot's `:stack-path` and an image `:part-rank`"* — no value; and no sentence anywhere in the contract says whether an image paints above or below its slot's rect background.

**Trace.** Cross-lane order inside one slot is decided entirely by `:part-rank`. Existing values are hand-assigned literals: shadow **0** (`renderer.cljs:2030-2031`), rect **1** (`:2046-2047`), slot-text **2** (`:2107-2110`); clip/partial-clear **0** (`:2011-2017`); every other frame entry defaults to **0** via `frame-order`'s 3-arity (`:1923-1927`). `compare-order` (`scene_tape.cljc:427-437`) compares, in order: stratum → pass-class → stack-path → **part-rank** → **stable-tie**. Nothing enforces part-rank uniqueness across lanes.

If the implementer picks `1` (colliding with rect), part-rank contributes zero and the decider becomes `stable-tie`, which for these entries is the entry-id (`frame-order`'s third arg at `:1977`): `[:frame/store vi :images]` vs `[:frame/store vi :rects]`. `compare-scalar` falls back to `(compare (pr-str a) (pr-str b))` for non-numbers (`scene_tape.cljc:393-397`), so `:images` sorts before `:rects` — **every image silently paints under every rect in its slot, decided by keyword spelling.** `W1.md:114-116`: *"`stable-tie` is used only after every semantic field ties; **it cannot replace missing sibling order.** Family identity and registration call order are not semantic z-order."* This is that exact substitution.

Second, sharper W1 problem: `W1.md:113` says *"`part-rank` orders **one material's** subparts (for example shadow before surface, surface before inline chrome)"*. The slot IS one material in the current model (`slot-entry`'s `:material/id`, `scene_store.cljc:238`), so shadow/rect/text-as-subparts is lawful. But §3 of this contract makes the image its **own** material (digest-keyed, its own revision). Ordering a *distinct material's* instances by a family-lane part-rank is not §3.1's part-rank semantics; the field §3.1 assigns to that job is `sibling-rank` (*"`sibling-rank` comes from the material/instance structure"*), and the one-entry-per-(vi, binding-run) shape cannot carry per-instance sibling rank. The consequence is a real, undeclared capability limit: an image authored between two rect siblings in the tree **cannot paint between them**.

**Exact repair.** §5/§7 gain three sentences: (i) the declared value and the total intra-slot lane order (e.g. *"shadow 0 → image 3 → rect 1 → text 2"* — pick an order and state it; reserve the integer), and G5 asserts part-rank uniqueness across all lanes; (ii) a named declaration that cross-lane collapse means tree-interleaved image/rect siblings paint lane-grouped, not interleaved — an **explicit declared order limitation** with per-instance sibling-rank entries as the named extension point (this is the honest, W1-conformant framing of what the pool-lane pattern costs); (iii) a trap (T13) that a part-rank collision routing order through `stable-tie` is a Contract-O violation, not a tie.
