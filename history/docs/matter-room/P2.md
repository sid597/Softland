## What P2 now does

### Deterministic composition

`app.shared.matter-room/residents` is the pure composition seam:

- head, bindings, then activation-trail residents oldest-first;
- deterministic identity-only turn ids
  `mr:<master-id>:<section>[:<pointer-revision-id>]`;
- stable composition ordinal and position;
- head/bindings marked refreshable;
- trail residents immutable and append-only;
- total behavior over nil, malformed, and entity-mode inputs.

Resident birth uses actor id `softland:matter-room`, legal platform actor type
`:agent`, role `"assistant"`, and part type `:material`. PLAN's literal
`:machine` actor type is invalid on the current platform:
`core/actor-types` contains `:human`, `:agent`, `:system`, and `:bot`.
Render-side machine classification is carried by the non-Sid actor id through
the projection hint's `role` slot. The resulting unit is the single
whole-block `:material-part`, not an N-block markdown fan-out.

Resident `:time-ms` at birth is the deterministic composition ordinal, not a
serve-time clock. The import payload is fingerprinted; a clock would make an
honest retry conflict. Any durable claimed time remains labelled in resident
text.

### Birth once, refresh monotonically, trail append-only

The four existing episode builders were parameterized without changing their
defaults:

- `utterance-actor` gained a one-arity while retaining its zero-arity;
- `utterance-rows` accepts optional actor id, actor role, and part type;
- `utterance-projection-hint` carries the supplied actor id in `role`;
- `utterance-import-request` threads the supplied actor into the same
  envelope.

Room birth calls that existing request builder, followed by the ordinary
object-container append and decision barrier. No new adapter, import family,
depot, PState, topology, or `extract-object-key` branch exists.

`open-matter-room!` reconciles pure composition against physical units:

- absent → birth through the episode import artery;
- present with equal bytes → unchanged, no write;
- present with changed bytes and refreshable → existing `:object/edit` artery;
- standing trail resident → append-only, never rewritten.

The edit lineage is the stable unit id, the edit client is
`softland:matter-room`, and the next edit sequence is read from the durable
`$$edit-order-by-target` row. A missing row means first sequence 1. A failed
durable read now propagates and fails the room-open request closed; it never
masquerades as a missing row.

A new pointer revision refreshes the single head resident and births exactly
one new trail resident. Previous trail residents retain their ids and bytes.

### Served entry and resident-widened experience

`POST /api/matter-room/open` materializes the deterministic room and returns
its room id, conversation object key, existing `?drill=<room-uuid>` entry, and
resident acts. The client exposes:

- `await __portal.room(masterId)`
- `await __portal.enterRoom(masterId)`

The served portal render gains one `room` row inside the existing identity
card; the closed card set is unchanged.

At a registered master anchor, the experience sub-serve reads room membership
through the existing episode projection API and calls
`experience-around-many` once for:

```text
[master-id ∪ room resident unit-ids]
```

The served experience reports those material ids, resident count, owning room
conversation address, and one relation roundtrip. A mark asserted on a
resident surfaces in the master's experience. Entity mode remains unchanged.

## Fresh falsifier — one agent, one failure, exact replay

The one authorized fresh falsifier initially found a real failure:
`matter-room-next-edit-seq` caught every durable PState read exception and
returned sequence 1. After accepted sequences 1 and 2, that fallback replayed
the old sequence-1 decision as `:accepted` while leaving physical sequence 2
and the old content unchanged—a silent lost refresh.

Smallest correction:

- remove only the catch-all around the durable sequence read;
- retain nil-row → first sequence 1;
- let read failure propagate before any edit request is constructed;
- add an executable regression.

The exact pre-fix attack changed from:

```clojure
{:nil-row 1, :prior-seq-7 8, :read-exception 1}
```

to:

```clojure
{:nil-row 1
 :prior-seq-7 8
 :read-exception [:thrown "forced durable read failure"]}
```

The same falsifier re-ran that exact attack, the four-concurrent-open attack,
and the changed-fingerprint/same-import attack after the fix. All passed. Its
final scoped verdict is **PASS**. The falsifier made no edits.
