    LLM Track / Codex Harness

    The 30-Second Grok

    Six ideas to walk in with

    If you read nothing else, read these. The rest of the doc unpacks them.

    01

    An agent is a stateful loop around a stateless LLM.

    Codex owns a flat list of typed items (user / assistant / tool_call / tool_result / reasoning). The model sees the whole list every inference. Number of model invocations per turn = (tool calls) + 1.

    → §1 Mental model
    02

    Reply is informed-by tool calls, not built-from them.

    There’s no atomic mapping “this sentence ← that tool call.” Don’t try to attribute spans programmatically. Preserve the trail; let the user navigate it. Sid’s rediscovery-over-consumption.

    → §1.1
    03

    The chat the model sees ≠ the chat the user sees.

    LLM-side view is frozen, immutable, what Codex emitted. User-side view is composed at render-time from raw items + world annotations + slices + edited derivatives + edges. The model never retroactively sees the right column.

    → §6.2 The unlock
    04

    The depot log IS the source of truth.

    Plural depots, singular truth. PStates are derived caches you can drop and replay. Topology is rules (no state). This is event-sourcing-shaped, not database-shaped — the instinct to look for “the” source-of-truth row is wrong.

    → §5.1
    05

    Forks are first-class. Threads form a DAG.

    Codex natively supports forking at item boundaries. Span-anchored forks are a Softland overlay. The conversation DAG and the discourse DAG are the same graph at different zoom levels — continuous semantic zoom you’re already designing toward.

    → §4 Forking semantics
    06

    For Sid, caching saves latency — not dollars.

    ChatGPT subscription = quota of messages, not tokens. UI surfaces “X of Y messages this window,” not “$X spent.” previous_response_id is a client-side state convenience — NOT billing-free. Cached prefixes (~50% off, ≥1024 tokens, ~5–10 min TTL) still count as input usage.

    → §3 Cost & caching

    The Unlock

    Two views of the same chat

    This is the reframe that dissolves the “where does the chat artifact live?” confusion. One frozen, one composed. Editing is authoring — it never mutates the LLM PState.

    LLM-side view

    FROZEN · IMMUTABLE · what the model saw
    • msg-1 user
    • msg-2 assistant
    • tool_call
    • tool_result
    • msg-3 user
    • msg-4 assistant

    Stored in $$llm-runs. LLM track owns content.

    User-side view

    COMPOSED · AT RENDER-TIME · what the UI shows
    • msg-1 user (+ annotation)
    • msg-2 assistant
    • ▸ slice A → notes-37
    • ▸ slice B → forked → chat-Y
    • msg-3 user (quotes msg-2 ¶2)
    • msg-4 assistant (bookmarked)
    • ↳ user-comment "this is wrong"

    Composed from $$llm-runs + world annotations + slice/quote artifacts + artifact-graph edges.

    The LLM never retroactively sees the right column. New turns receive a ContextBundle that may render parts of it.
    Hard-Won Learnings

    What this conversation actually figured out

    Each is a place where naive intuition would have led you wrong — and the doc preserves both the trap and the correction.

    §1.1

    Don’t span-attribute the reply

    Sentence-level provenance from reply-text back to specific tool-result tokens is weak — would require asking the model and trusting self-report. Stop at item-level provenance; let the user navigate.

    §5.6

    Cross-track handshakes are the breakage point

    Chat lives in LLM PState but isn’t catalogued in world — classic foreign-append failure. Use :append-ack on state-transition events; bare appends only for high-frequency deltas.

    §5.2

    Topology is the only writer of PStates

    Every PState row has exactly one place to look to ask “how did this get here?” — the topology branch handling the depot event. You never chase mutations across services.

    §3.5

    Compaction destroys the trail (for the model)

    After thread/compact, the model only sees the summary on subsequent runs. Softland’s trail in Rama survives. Compact-then-fork is cheaper than fork-then-compact — all forks inherit the smaller prefix.

    §6.3

    Editing is authoring, not mutation

    “Edit the LLM’s reply” lands as a new world annotation artifact. The LLM PState is unchanged. Distinguish overlay (annotation) vs derivative (replacement-version) — collapsing them weakens the canvas vision.

    §4.3

    Conversation DAG = discourse DAG

    At different zoom levels, they’re the same graph. Multi-fork doesn’t destroy parents; reconciliation creates a new node; all parents remain. Preserved plurality is the default; synthesis is late-bound transformation, not summary.

    §9.3

    Slice writes to world, not LLM

    Selecting a span and clicking “slice” appends :slice/create to *world-action. Writes $$slices, $$objects, and an artifact-graph edge. Raw item is immutable. The slice is a sibling, not a mutation.

    §12.3

    Spine becomes ceiling without breadth labels

    Codex compresses; reviewers always do. Most-at-risk concepts: custom tools (back-arrow not visible), reconciliation (multi-parent ContextBundle), discourse graph (typed projection), canvas (UI layer). The four ★ labels are how you keep them from being forgotten.

    Decisions

    What's settled, what's open

    The doc captures four decisions made over the course of the conversation, and four still open for Sid. Open ones are not cross-model decidable — they’re value calls.

    Settled

    Surface: codex app-server
    Not exec --json — that strips deltas, raw reasoning, and hardcodes auto-reject for approvals. app-server gives the full ~78-variant event stream, mid-conversation injection, and approval forwarding.
    Architecture: World-first / Pattern Y is canonical
    Closed in v2. UI never writes *llm-depot directly. UI → *world-action → WorldTopology composes the bundle and foreign-appends to *llm-depot. Pattern X is gone, not deferred.
    Default: preserved plurality, not programmatic merge
    Reconciliation creates a new node; all parents remain. Synthesis is transformation of preserved plurality — not summary. “Late-bound consensus.”
    Approval policy: on-request
    Codex blocks the turn with no internal timeout. Softland MUST enforce wall-clock timeout (~5 min) and reply {"decision":"decline"}. --yolo only inside another sandbox.
    Forks are thread-level only
    Codex’s thread/fork takes threadId + config — no fromItemId. Span and item anchoring is a Softland overlay via slice-and-quote. The earlier “fromItemId” reading was wrong.
    Auth: ChatGPT subscription via PKCE
    One-time codex login; auto-refresh; on permanent refresh failure surface as re-login required. Strip OPENAI_API_KEY/CODEX_API_KEY from spawn env. Never persist auth.json or JWT claims to Rama.

    Open · Sid-decidable

    1. ContextBundle physical home
    Own depot (*context-bundle-depot)? Or topology-internal (composed in WorldTopology at SEND, stored on $$context-bundles before foreign-append to *llm-depot)? Either way authored on the World/Context side — the choice is where in that side it lives.
    Trade-off: auditability vs hop count.
    2. World derivatives organization
    Single PState ($$world-derivatives) vs kind-typed many ($$edited-messages, $$curated-excerpts, $$synthesized-notes).
    Trade-off: simplicity vs queryability.
    3. Derivative versioning
    Edit twice → keep both versions, or single mutable artifact? Versioned matches event-sourcing instincts; mutable saves storage.
    Trade-off: history vs storage.
