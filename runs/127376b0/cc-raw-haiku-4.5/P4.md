# Answer to P4: Transcript-Commit Join Representation Ruling

**Who ruled:** Fable

**Authority:** Sid's in-session time-box blanket ("use the recommended option, note the others"); reversible on Sid's review

**Date of ruling:** 2026-07-05

**What was decided:**

The transcript↔commit join representation was ruled to use **durable import-asserted RelationEdges** with the following specifications:

1. **Asserter-type:** `:import`
2. **Actor-id:** Version-free `"import:git-spine"` (not version-specific)
3. **Evidence:** References to transcript session + entry (evidence-source-id + evidence-anchor-id)
4. **Verification:** SHA hashes verified against the repo before asserting
5. **Exactness marking:** Documented via note-grammar v1 (promoted to a structured field only when a view demands rendering it differently, following D-001's principle)

**Alternative considered but not taken:**
Projection-time joins (which avoid storage/staleness concerns but cannot carry `asserted-by`/exactness/retraction properties and would require new query topologies per join type)
