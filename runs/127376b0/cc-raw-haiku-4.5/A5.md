# Answer to A5

## Where do current decision statuses live, and where does the single 'now / current work' state live?

### Decision Statuses

Current decision statuses live in **`docs/current-mental-model/decisions.md`**, described as "the binding decision log (D-001+, countersigned by Sid)" (CLAUDE.md, §Decision Log — BINDING).

Each decision has a STATUS field that is either **CLOSED** or **PROPOSED**:
- **CLOSED**: decisions that have been countersigned by Sid; reopening requires "evidence of a *used form breaking against them* — never a new argument, research round, or model opinion" (decisions.md, Operating rules)
- **PROPOSED**: new rulings awaiting Sid's countersign

Examples from the log:
- D-001 through D-005: **CLOSED** (countersigned 2026-07-03)
- D-006: **CLOSED as a bet** (placed 2026-07-03; evaluation pending, criteria fixed below)
- D-007: **CLOSED** (proposed by Fable 2026-07-03, countersigned by Sid 2026-07-04)
- D-008: **CLOSED** (drafted by Fable 2026-07-04, countersigned by Sid 2026-07-04 in-session)

### Current Work State

The single 'now / current work' state lives in **`docs/sessions/next-prompt.md`** under the "⚡ BATON" section, marked "READ FIRST; supersedes everything below" (next-prompt.md, header).

The file explicitly states this hierarchy:

> "This file is a baton, not a source of truth; if it contradicts CONTRACT.md or decisions.md, those win — flag the discrepancy in NOW." (next-prompt.md, Active work package: trail-view WP1, STANDING)

AND:

> "if this contradicts CONTRACT.md or decisions.md, those win — flag the discrepancy in NOW." (next-prompt.md, Active work package: view-MVP WP-B2, STANDING)

The NOW section is explicitly capped: "append ≤15 lines at session end" (next-prompt.md, trail-view WP1, NOW header).

The baton tracks:
- What was completed this session
- Uncommitted code in the working tree
- Next steps in exact order
- Open work-package states (STANDING frozen at package open; NOW appended at session end)

### The Pace-Layer Rule

The memory protocol states this design principle: "MEMORY.md is the **index and soul**, not a dumping ground" and "Pace-layer rule (memory hygiene): memory files hold **invariants** and **dated events** (provenance — ages like a git commit). They never hold **dated states** — 'as of', 'currently', 'awaiting' rot on write. 'Now' lives in exactly one file: `docs/sessions/next-prompt.md`" (memory/MEMORY.md, Pace-layer rule).
