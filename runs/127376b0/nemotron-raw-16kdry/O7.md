**Answer**

The first face that renders in the trail‑view UI is the **View 3 data‑layer face** (the minimal‑token‑legibility “data‑only” view).  

**Why:**  

1. **Decision D‑002** explicitly declares the *trail view* to be the *first form* that must appear in Softland — the view that answers “where are we / how did we get here / what crossroads did we take” and is rendered **over Softland’s own material** (code, git history, docs, chats). [^1]  

2. The subsequent ordering decisions (the “view‑first” design in the *vision/design‑brief* documents and the *build/trail‑view/CONTRACT* file) place the **View 3** layer first, then the threaded/DAG timeline, then the canvas. This ordering is required so that the MVP can render a **pure data surface** before any write‑capable UI is introduced. [^2]  

3. Because the MVP must be *read‑only* (the first form cannot involve any write operation), the only face that satisfies that constraint is the View 3 data‑layer, which mirrors the relation‑kernel query topologies and provides the context‑bundle surface without any mutation.  

Thus, the **View 3** component is the first thing that appears on screen when the trail view is rendered.
