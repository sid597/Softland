=== Sheet | The store — the questions the gates need

Choose in this order. Tick a box, and write on the line when a choice asks for words. Each question keeps its number from the papers you hold: a Q is a circle on the ladder sheets; an F is a row of the list of all decisions. 7 October 2026.

## Words on this sheet

- **fact** — one statement: an entity, a key, a value. "Key" on this sheet always means a fact's key.
- **act** — one or more facts that one maker sends to the store under one name. A gate accepts all of it or refuses all of it.
- **maker** — whoever makes an act: a converter, the screen, an agent.
- **the one form** — the fixed set of ten parts that every act has, whoever made it, so that one piece of code can check every act.
- **the check** — the code that takes anything and says "an act" or "not an act, because …".
- **session** — the session that an act belongs to. Every act carries its session.
- **layer** — the one place in the store that an act writes to: the base that all share, a group's, a person's, or a session's.
- **class** — which of the two gates decides the acts of a layer: streaming or microbatch. It is a fact on the layer. A **streaming layer** has the class streaming; a **microbatch layer** has the class microbatch.
- **the door** — the code that takes an act from a maker into the store. It makes the name, adds the class from the layer, and seals the values.
- **depot** — a log in Rama that keeps each act appended to it, in order, until a trim. Any client can append to a depot and read it.
- **trim** — Rama removes the oldest acts of a depot when it holds more than a set count.
- **gate** — code inside the store that reads a depot and decides each act: accept or refuse. The **streaming gate** decides one act at a time, on the one task of the act's layer, in milliseconds. The **microbatch gate** decides many acts together, on all tasks, one batch later.
- **record** — what the gates keep: the accepted facts, and each answer under its act's name.
- **answer** — a gate's result for an act: accepted, or refused with a reason word.
- **name** — the id of an act: [layer class id]. The door makes it.
- **stamp** — the time mark that a gate puts on an act when it accepts it.
- **seal** — encrypt a value with its **lock**, so that "forget" can later destroy the lock. A lock is an encryption key, never a fact's key.
- **store key** — one of the fact keys that the store itself acts on: a class, a permission, a forget, and others.
- **permission** — who may act in a layer: [who layer granted-in].
- **Rama** — the system under the store. It keeps the depots and the PStates, and it runs the gates.
- **task** — one of the N divisions of the store inside Rama. Each task has one thread. N is fixed at the start.
- **PState** — data that a gate keeps inside Rama. One gate writes it. It is kept on disk when it is written; it is not made again from a depot.
- **attempt** — one run of a gate's work for an act. After a failure Rama makes a new attempt.
- **ack** — what Rama returns to a sender after the sender appends an act to a depot.
- **re-class** — a change of the class of a layer.
- **promotion** — the move of a value from one layer into another layer. It is two acts.
- **the first kept record** — the first act that the store keeps for good. A choice that is frozen at the first kept record cannot change after it without splitting the store into acts before and acts after.
- **the rig** — an example build of the store on Rama, 25 September. Its findings are evidence.
- **the 2 October drawing** — the drawing of the store in `ARCHITECTURE-STE100.md`.
- **the ladder** — your printed map of the store, from the sources down to the depots.
- **the rulings file** — `src/proposal/frame-2026-09-15/PROGRESS.md`, "Now".

=== F6 | Two depots, or one

- **partitioner** — the rule by which a depot picks the task for an act.

```
 two depots   the door reads the class of the layer, then appends to one of two:
                streaming depot     picks the task by the layer     read by the streaming gate
                microbatch depot    picks the task by an entity     read by the microbatch gate

 one depot    the door appends to the one depot
                its partitioner reads the class that the door added, and picks the task
                both gates read it; each gate drops the acts that are for the other gate
```

Ruling 1 in the rulings file says "two fact stores, each with its own gate". It gives no number of depots.

**Do the acts go to two depots, one for each gate, or to one depot that both gates read?**

[ ] **A** — two depots, one for each gate.
If A: the door must know the class of the layer before it appends; each depot has one gate that reads it.
[ ] **B** — one depot, with a partitioner of the store's own.
If B: the door picks no depot; each gate reads each act and drops the acts that are not its own. Q7 then asks for one word.

Today: the store's tree has no depot. In Rama a depot is only a log, and Rama lets the store give a depot a partitioner of its own. The ack of an append waits only for the streaming gates that read that depot. Frozen at the first kept record.

=ANSWER A or B.

=== F2 | Where the record is

```
 in the PStates of the gates     a gate decides an act and writes the record in one step:
                                 the two happen together, or not at all

```

**Where do the gates keep the record?**

[ ] **A** — in the PStates of the gates.

=== F1 | Who sets the class of a layer

- **kind** — what a layer is: the base, a group's, a person's, or a session's.

```
 24 September, four ruled lines      the kind of layer sets the class:
                                     a layer with one owner is a streaming layer
                                     a shared layer is a microbatch layer

 2 October, the third switch         the members of the layer set the class,
 (the 2 October drawing records      by the policy of the layer
  it as agreed that day)
```

The four lines are ruling 1, ruling 2, "Layer kinds", and the first of "Two consequences", in the rulings file.

**Does the third switch of 2 October replace the four ruled lines of 24 September?**

[ ] **A** — yes. The class is a fact that the members set, for each kind of layer.
If A: a group can make its shared layer a streaming layer, with answers in milliseconds; a busy streaming layer slows the others on its task, and each microbatch layer.
[ ] **B** — no. The kind of layer sets the class. Write on the line what of the third switch stays.
If B: each shared layer is a microbatch layer, where an act shows one batch later and a person who types sees a lag. This settles F4: C.

Today: no code of the store sets a class. The act's name has a class slot, :streaming or :microbatch, which the door fills from the layer. A layer's class can change later by a re-class; after it, each read of that layer joins the acts before the re-class with the acts after it, for the life of the layer. The rule itself is free.

=== F5 | Where a streaming gate finds a grammar

- **grammar** — a fact that gives the shape of the values for a key. A gate checks each value against it.

A streaming gate decides one act in one step, on the one task of the act's layer. In that step it can use what is on that task; what is on another task, it must fetch. The same question holds for the rules that say which indexes the store makes.

```
 on the gate's own task     the layer · its permissions · its current facts
 the grammar                in this layer too   ─ or ─   in one place, on another task
```

**Where does a streaming gate find the grammar that it checks a value against?**

[ ] **A** — each layer holds a copy of each grammar that it uses.
If A: the gate needs no fetch; a change to a grammar is a change in each layer that holds a copy.
[ ] **B** — a grammar is in one place; the gate fetches it from another task and records that read.
If B: each grammar is in one place; each act costs one fetch, and the grammar can change between the fetch and the decision.

Today: no gate of the store is built, and the 2 October drawing leaves this open. Frozen at the first kept record: it says what each layer holds.

=ANSWER A or B.

=== Q22 | How a streaming act gets its answer

The rulings file says: "An answer is found by name plus layer."

```
 on the ack   the door appends the act ─► streaming depot ─► the streaming gate decides
              the ack comes back to the door with the answer in it

 by name      the door appends the act ─► streaming depot ─► the streaming gate decides and records
              the door asks the record: "which answer is under this name?"
```

**Where does the door take a streaming act's answer from?** Choose it together with F7.

[ ] **A** — by name: the door reads the answer from the record; the ack is not the answer.
If A: the answer always comes from what the gate recorded; each act costs one more read.
[ ] **B** — on the ack: after an error, the door sends the same bytes again, and the gate gives the answer that it recorded under that name.
If B: each act costs one trip to the depot and back; the door takes an answer only from a sending that worked.

Today: the store's tree has no door; it comes with the store's own gates. Findings of the runs of 25 September and 2 October: an ack can be an error for an act that the gate accepted, and Rama can run a gate's work for one act more than once, so a gate reads its record by name before it decides. A microbatch act gets no answer on the ack. Free: it is the door's code.

=ANSWER A or B.
