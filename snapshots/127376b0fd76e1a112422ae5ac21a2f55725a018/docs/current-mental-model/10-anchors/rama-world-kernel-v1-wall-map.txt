========================================================================
2. CONTRACT TABLE
========================================================================

  +-------------------+-----------------------------------------------+
  | contract          | responsibility                                |
  +-------------------+-----------------------------------------------+
  | action-request    | Durable request for the world to interpret.   |
  | event             | Durable accepted fact from an ActionRequest.  |
  | target            | Stable reference to what the action is about. |
  | action            | Interpreted operation over a target.         |
  | materialization   | Reader-friendly PStates derived from truth.  |
  | projection        | View over materialized state.                |
  | policy            | Gate observations and actions.               |
  | distillation      | Versioned derivation of units/relations/etc. |
  +-------------------+-----------------------------------------------+

  Materialization is not source truth.
  Projection is not source truth.
  KernelEvent is source truth only after acceptance.
  ActionRequest is source truth that someone asked.
  ActionDecision is source truth that Rama answered.

3. ACTIONREQUEST ENVELOPE
========================================================================

  +------------------------------------------------------------------+
  | ActionRequest                                                     |
  +------------------------------------------------------------------+
  | :request/id                                                       |
  | :request/type                                                     |
  | :request/time-ms                                                  |
  | :request/schema-version                                           |
  | :routing/key                                                      |
  | :actor                                                            |
  | :branch                                                           |
  | :context                                                          |
  | :target                                                           |
  | :action                                                           |
  | :payload                                                          |
  | :causal                                                           |
  | :provenance                                                       |
  | optional: :proposed/event-id                                      |
  +------------------------------------------------------------------+

  ActionRequest is intentionally not an accepted world fact.
  It is an ask, not a happened event.

  Important invariants:

    :request/type must equal [:action :action/type]

    :routing/key must exist and be a non-empty vector with no nil parts

    :event/id must not appear at the top level

    [:payload :event/id] must not appear

  Proposed event id:

    :proposed/event-id may exist for deterministic tests.
    It is not a KernelEvent.
    It becomes a real :event/id only if the request is accepted.


========================================================================
4. ROUTING KEY CONTRACT
========================================================================

  routing-key-contract:

    {:kind :semantic-vector
     :transitional? true}

  Current key shape:

    [:artifact artifact-id]

  routing-key-for chooses, in order:

    1. [:artifact (:artifact/id payload)]
    2. [:artifact (artifact-id-from-unit-id (:unit/id payload))]
    3. [:artifact (get-in target [:target/address :artifact/id])]
    4. [:artifact (:target/id target)] when target kind is :artifact
    5. [(target-kind or :target) target-id]
    6. [:request request-id]
    7. [:request "unkeyed"]

  Honest locality map:

    ActionRequest
        |
        | depot partitioned by semantic vector
        v
    *world-requests-depot  (hash-by :routing/key)
        |
        | topology often re-hashes to physical PState keys:
        |
        +--> |hash request-id    for $$requests-by-id
        +--> |hash decision-id   for $$decisions-by-id
        +--> |hash event-id      for $$events-by-id
        +--> |hash branch-id     for $$branches
        +--> |hash artifact-id   for artifact/text/unit PStates

  This is better than random depot routing.
  It is not yet perfect physical Rama locality.

8. AUTHORIZATION REALITY
========================================================================

  authorized-request? currently does this:

    system actor:

      allowed

    non-system actor:

      required capability = [:action :action/capability]
      actor capabilities  = [:actor :actor/capabilities]
      allowed if actor capabilities contain the required capability

  Current policy caveat:

    $$policies exists.
    default-policy exists on KernelEvent.
    But the live authorization check currently reads the request actor
    capabilities, not a full Rama-owned policy PState.

  So V1 is honest about the request/decision/event contract.
  Policy is still a quiet shelf, not the center of this pass.

========================================================================
12. REQUEST -> EVENT DERIVATION
========================================================================

  ingest-request->event:

    event id:

      (:proposed/event-id request)
      or
      request-id + "/event"

    causal:

      {:parents []
       :correlation/id request-id
       :intent/id request causal intent id}

      merged with request :causal

    provenance:

      {:source/type :action-request
       :source/ref request-id}

  status-request->event:

    same event id rule:

      proposed id or request-id + "/event"

    same causal/provenance rule:

      correlation id points back to request

  compat-request->event:

    event id:

      request-id + "/event"


========================================================================
13. INTERPRETERS AND REJECTION REASONS
========================================================================

  decide-event:

    event-validation-errors
          |
          +--> errors present:
          |       rejected-decision :derived-event-invalid
          |
          +--> no errors:
                  accepted-decision

  interpret-ingest-request:

    request invalid      -> :request-invalid
    unauthorized actor   -> :actor-not-authorized
    otherwise            -> derive ingest KernelEvent, decide-event

  interpret-status-request:

    request invalid      -> :request-invalid
    unauthorized actor   -> :actor-not-authorized
    unit missing         -> :target-unit-not-found
    invalid status       -> :unit-status-invalid
    otherwise            -> derive status KernelEvent, decide-event

  interpret-compat-request:

    request invalid      -> :request-invalid
    unauthorized actor   -> :actor-not-authorized
    otherwise            -> derive compat KernelEvent, decide-event

  unknown-action-decision:

    valid request but unknown action type -> :unknown-action-type

========================================================================
17. TOPOLOGY: FULL CONTROL FLOW
========================================================================

  source:

    source> *world-requests-depot :> *request

  extract:

    request-id          -> *request-id
    request-action-type -> *action-type
    request-validation  -> *request-errors

  first gate:

    request-errors?
        |
        +--> true:
        |     rejected-decision :request-invalid
        |     store request
        |     store decision
        |     STOP
        |
        +--> false:
              dispatch by *action-type


  ----------------------------------------------------------------------
  Branch A: :artifact/ingest
  ----------------------------------------------------------------------

    interpret-ingest-request
        |
        v
    ActionDecision
        |
        +--> always store request in $$requests-by-id
        |
        +--> always store decision in $$decisions-by-id
        |
        +--> if rejected:
        |       no KernelEvent
        |       no artifact materialization
        |       no text revision
        |       no units
        |
        +--> if accepted:
                decision-event -> *event

                event-id        -> *event-id
                branch-id       -> *branch-id
                artifact-id     -> *artifact-id
                revision-id     -> *revision-id

                branch-materialization   -> *branch
                artifact-materialization -> *artifact
                revision-materialization -> *revision
                units-by-id-materialization -> *units

                |hash event-id
                  $$events-by-id[event-id] = event

                |hash branch-id
                  $$branches[branch-id] = branch

                |hash artifact-id
                  $$artifacts[artifact-id] = artifact
                  $$artifact-heads[artifact-id] = revision-id
                  $$text-revisions[artifact-id][revision-id] = revision
                  $$units-by-artifact[artifact-id] = units


  ----------------------------------------------------------------------
  Branch B: :unit/status-set
  ----------------------------------------------------------------------

    request-artifact-id -> *artifact-id
    request-unit-id     -> *unit-id

    |hash artifact-id
      local-select $$units-by-artifact[artifact-id][unit-id] -> *unit

    interpret-status-request with request + unit
        |
        v
    ActionDecision
        |
        +--> always store request in $$requests-by-id
        |
        +--> always store decision in $$decisions-by-id
        |
        +--> if rejected:
        |       no KernelEvent
        |       no status materialization
        |
        +--> if accepted:
                decision-event -> *event

                event-id   -> *event-id
                branch-id  -> *branch-id
                unit-id    -> *unit-id

                branch-materialization -> *branch
                status-materialization -> *status

                |hash event-id
                  $$events-by-id[event-id] = event

                |hash branch-id
                  $$branches[branch-id] = branch
                  $$unit-status-by-branch[branch-id][unit-id] = status


  ----------------------------------------------------------------------
  Branch C: :compat/record
  ----------------------------------------------------------------------

    interpret-compat-request
        |
        v
    ActionDecision
        |
        +--> always store request in $$requests-by-id
        |
        +--> always store decision in $$decisions-by-id
        |
        +--> if rejected:
        |       no KernelEvent
        |
        +--> if accepted:
                decision-event -> *event

                event-id  -> *event-id
                branch-id -> *branch-id

                branch-materialization -> *branch

                |hash event-id
                  $$events-by-id[event-id] = event

                |hash branch-id
                  $$branches[branch-id] = branch


  ----------------------------------------------------------------------
  Branch D: default unknown action
  ----------------------------------------------------------------------

    only reached after common request validation passes

    unknown-action-decision
        |
        v
    rejected ActionDecision

    store request in $$requests-by-id
    store decision in $$decisions-by-id
    no KernelEvent

    task count:   4
    thread count: 2

    returns foreign handles:

      :world-requests-depot
      :requests-by-id
      :decisions-by-id
      :events-by-id
      :artifacts
      :artifact-heads
      :branches
      :policies
      :text-revisions
      :units-by-artifact
      :unit-status-by-branch
      :projection-cache

  close-kernel-runtime!

    closes IPC

  append-action-request!

    foreign-append! request into *world-requests-depot
    append ack
    returns request

    $$events-by-id[event-id]

    $$branches[branch-id]

  read-artifact:

  read-text-head:

    $$text-revisions[artifact-id][revision-id]

  read-units:

    $$units-by-artifact[artifact-id] or {}

  read-unit-statuses:

    $$unit-status-by-branch[branch-id] or {}

  await-materialized:

    poll read-f until pred passes or timeout
    default timeout: 2000 ms
    sleep interval: 25 ms

  await-decision:

    await read-decision

21. HIGH-LEVEL RUNTIME HELPERS
========================================================================

  ingest-text!

    build ingest-text-request
    append ActionRequest
    await ActionDecision
    return accepted event or throw

  unitize-lines!

    wait until units exist for artifact
    return units sorted by :unit/order

  set-unit-status!

    build unit-status-request
    append ActionRequest
    await ActionDecision
    return accepted event or throw

26. WHAT IS FULLY V1 NOW
========================================================================

  ActionRequest has a real contract.

  :routing/key is required.

  Request depot uses :routing/key.

  :request/type and :action/type cannot drift.

  :event/id cannot be smuggled onto ActionRequest.

  Common request validation happens before action dispatch.

  Unknown action does not bypass common validation.

  ActionDecision carries :routing/key.

  Rejected ActionDecision has :event/id nil.

  Accepted ActionDecision has the accepted event id.

  KernelEvent provenance points back to ActionRequest.

  KernelEvent causal correlation points back to ActionRequest.

  PStates materialize only from accepted KernelEvents.

  Rejected requests remain durable as requests and decisions.

  Routing locality is documented as transitional, not oversold.

========================================================================
28. THE WALL CHECKSUM, LONG FORM
========================================================================

  Before changing Rama, ask:

    1. Is this an ActionRequest, or am I trying to sneak in an event?

    2. Does the request have a real :routing/key?

    3. Does :request/type match [:action :action/type]?

    4. Does validation happen before dispatch?

    5. If malformed, does it become :request-invalid?

    6. If unknown but well-formed, does it become :unknown-action-type?

    7. Does the decision preserve :routing/key?

    8. If rejected, is :event/id nil?

    9. If rejected, is there no KernelEvent?

   10. If accepted, is the event id born at the decision boundary?

   11. Does KernelEvent causal/provenance point back to the request?

   12. Does all reader state come from accepted KernelEvents?

   13. Is the locality story true, not aspirational?

   14. Did I use $$policies or $$projection-cache only if I really wired them?

  ActionRequest asks.
