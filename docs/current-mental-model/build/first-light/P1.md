## Three perf findings (all measured, all fixed — the G1 story)

The naive flip FAILED G1: narrow echo p50 52/p95 58.7/p99 162 with 150ms
stalls (pre-flip control 19.9/24.2/27, 0 stalls). Wire-level split
(WebSocket send/message wrap): the envelope left in 0.5ms; the +30ms sat in
delivery. CPU profile (Chrome trace) attribution:

1. **In-propagation build**: building the slot inside the `m/latest`
   combine put 7-15ms into every keystroke/decision/truth turn. Fix: the
   bundle-emit + coalescing-microtask consumer (killed the 150ms tail).
2. **Exact-size GPU buffer growth**: `ensure-text-instance-buffer` grew to
   exactly required size, so the slot text geo (cloned at 256) re-allocated
   a GPUBuffer EVERY keystroke (+1 glyph). The content geo never hit this
   only because its 10k initial capacity was slack. Fix: 1.5× growth slack.
3. **`glyph-map` rebuilt PER LINE** in shape-msdf/slug-line — a
   whole-conversation reshape rebuilt the full unicode→glyph map hundreds of
   times per keystroke (~23ms/keystroke, 460ms of 20-keystroke profile).
   Fix: WeakMap cache keyed on the font glyphs vector identity. Benefits
   every text path (content, chrome, slots, spawned copies).

## Judgment calls + open doubts (non-blocking, falsifiers named)

- `<store-frame` now merges slots in deterministic order (main face first,
  then by vi) — preserves copies-paint-over-main from the legacy append
  order.
- Render's destructive `close-all-slots!` re-checks the LIVE mode atom
  before closing (the sampled world lags one frame; a stale-world close on
  face-mode entry would blank the face until the next rebuild).
- `build-slot` accepts `:pre-resolved?` (main-face path skips the second
  resolve; resolve-layout is idempotent — opt-in, mutated trees still
  resolve). `stamp-block-addresses` is structure-sharing now.
- **Open doubt 1**: pre-flip face typing showed NO text reshape in the CPU
  profile (the reshape chain looks reachable in the old code — unexplained,
  and now unreachable). Falsifier: profile editor-mode (file-workspace)
  typing for `update-text-data` frequency; if the content path reshapes per
  keystroke there, finding 3's cache now covers it too.
- **Open doubt 2**: one ~128ms echo outlier per ~200 keystrokes (GC-class,
  stall forensics k=54/k=151 mid-run). S3 p99 passes; watch during P6 wear.
