## 4. The wish and the repair (P3–P5) — the unit, executably

- **Wish = material + coupling + projection, never a transport field.**
  A wish is an OC unit in the episode (durable, addressable, asserted-by
  its wisher) COUPLED to its target by a `:references` relation edge — an
  EXISTING kind, semantically honest ("about"), zero enum growth. The
  wish's wish-ness lives in its material and its projection, not the edge
  kind; a dedicated Wish kind waits for recurrence (DIRECTION: names
  finalize by recurrence — and the relation kernel's growth rule wants a
  proven consumer first).
- **Point supplies the target**: pick on conversation material returns
  {vi, address, src-path} (P1's seam); the wish unit records both the
  material address and the face src-path it was uttered against.
- **The candidate is a FORK, never a revision of the active face.** Trap
  T3 (below) is load-bearing: importing onto `asm:<name>` auto-advances
  `current-revision-id` and the live re-render loop would flip the worn
  face WITHOUT any accept. So: the agent's proposal lands as assembly
  source under its OWN name (`asm:<name>--wish-<n>`), `:assembly/status
  :candidate`, `based-on` edge to the original — entering through a
  **string-source import entry** (the watcher's slurp path minus the file;
  `assembly-source-import-request` already takes source text — RECON Q2).
  This deliberately opens framework §20.3's machine-written-assembly
  non-goal; the framework contract's own extension point, exercised here
  with provenance (`:assembly/author` = the agent, visibly silver).
- **Preview = the draft-face membrane on the plurality path.** The
  candidate compiles client-side by NAME (the second assembly artery —
  P3c's staged item, pulled in because the used form now needs it) and
  renders as its own view-instance against the LIVE conversation
  projection, the worn face untouched (the store was built for exactly
  this — RECON Q1: "N different arsenal faces render one live
  conversation").
- **Accept** = import the candidate's source onto the ORIGINAL
  `asm:<name>` (a new revision through the existing chain; the Step-7A
  loop re-renders the inhabited face), plus lineage: `produced` /
  `supersedes` edges recording wish → proposal → decision → revision.
  **Reject** = the fork stays in the trail as `:candidate` (or `dead-end`
  edge — Sid's word), active face untouched. **Reverse** = re-import the
  prior revision's content (history is append-only; nothing deletes).
- **"Why is this here?"** = at point of use: pick the changed region →
  the trail chain (wish material → proposal material → decision → revision)
  served as a projection over existing reads. The inspect verb's first
  lived form.
- **Behavioral wishes route honestly**: if the first real friction is not
  arrangement-expressible, the wish still lands as material + coupling and
  the land says so — it becomes the code lane's originating pressure. The
  arrangement gate keeps waiting (no-fabrication, §7 G9).

  `overlay-face-context` (edit-state + truth-overlay) into the per-vi

- **T6 — double-draw** (P3c wall 2): the legacy face-mode text/rects
  consumers are silenced the same frame the slot lands, or the main face

- **T7 — stamp BOTH identities**: root :view-instance/:address (exists)
  AND per-block `[:data :address]` (store path only) — else picks resolve

- **T8 — post-turn re-distill must be idempotent** — deterministic import
  keys make re-runs converge (the migration-day receipts prove the class);

- **T9 — the ground ships BARE; no scaffolding leaks into it — and BARE

- **T10 — no fabricated friction.** G9 waits for a real arrangement
