## Shape of the package

The package connected the existing object-container `:object/edit` organ to a
reader-face editing surface. It did not create a second write system. Work ran
contract -> Phase 0 resolution pin -> two lanes -> INT -> one falsification
finder -> gate fixes -> headed measurement -> Sid ruling -> corrected wearing
and full-process restart -> WAL mini-falsification -> close suites. The package
opened and reached code gate on 2026-07-12; its corrected durability proof and
close completed on 2026-07-13.

## QC-layer scorecard

1. **Contract + Phase 0 caught a category error before code.** The first
   plausible `document-container-id` reading used the conversation container.
   Echo would have worked, but durable lineage would have lied: the rendered
   derived unit's real parent is its per-message container. Phase 0 pinned the
   already-read unit field and preserved provenance with zero extra reads.
2. **The two implementation lanes were narrow and first-run green.** Lane A
   added the projection field and reused the Rama edit path; Lane B built the
   pending-input/caret state machine and outbox. Their boundary stayed additive:
   no second depot, topology, container identity, or client hash rule appeared.
3. **INT caught the first product-path failure.** Rama truth changed, but the
   river projection still preferred raw derived text, so the face echoed 0/120
   and restart survival was absent by construction. S2 fired, the overlay path
   was fixed, and the relevant regression suites went green before proceeding.
4. **G7 measured the real design instead of blessing a demo.** The narrow truth
   pull met the 50 ms p95 bar, while the inherited one-stall-per-minute clause
   failed on a thin roughly 130 ms tail. Sid ruled p95 <= 50 ms and p99 <= 100
   ms; optimistic echo remains forbidden. The same run exposed F4: long-block
   whole-face work plus relieved keyboard flow can drop input, now a named LATER.
5. **One falsification finder paid for itself.** It found the HIGH cross-unit
   stale-overlay path that could later overwrite good truth, plus bounded state
   growth and refusal-lifecycle defects. The union request map, clear-all prune,
   64-entry bounds, and refusal clearing landed with regressions. Its commit
   hygiene finding also prevented probe namespaces from entering release scope.
6. **Wearing caught what every suite and the first live report missed.** The
   original 07-12 "restart-survival observed live" claim was false: the client
   had reconnected without replacing the JVM, and pre-WAL full-restart survival
   was architecturally impossible. Correct same-conversation, same-unit testing
   forced the WAL addition and a two-runtime regression.
7. **The refusal pixel red was an identity/viewport error, not a renderer bug.**
   `setup(4)` focused an offscreen sense-block duplicate while the screenshot
   showed identical whole-message prose. Moving the actual focused block into
   view painted the notice. No kernel or renderer change was needed; the probe's
   repeated request id was made unique.
8. **The corrected wearing earned the close.** A non-precious fixture pre-drill
   proved accepted edit, stale revert, visible reason, and exact-unit survival.
   Sid then wore the real path: suffix `hello` accepted; stale `x` reverted;
   `edit refused: stale` visible; fresh JVM boot reported 10 replayed / 0 failed;
   the same accepted text remained. This is the first honest G8 receipt.
9. **The process rule caught an operational failure cleanly.** A disk-full boot
   failure was reported immediately, not hidden inside repair. With no live JVM,
   20 orphaned Rama IPC directories were identified and removed, recovering
   152 GB; the retry and final suites were green.

## What the next contract should do differently

1. **A restart claim names the replaced process and the exact identity checked.**
   "Restarted" is insufficient. The receipt must name old/new JVM, conversation,
   unit, expected text, and authoritative replay line.
2. **An ephemeral-runtime durability contract names its reconstruction order.**
   WAL replay is only meaningful after each target's imported base exists.
   Default-conversation readiness does not imply arbitrary-conversation readiness.
3. **A WAL contract states the durability level explicitly.** Writer close/flush,
   filesystem `fsync`, torn-tail recovery, and compaction are separate claims.
   This package proves the first plus malformed-line isolation, not host-crash
   tail durability.
4. **A wearing harness focuses by visible identity.** Test setup must stage the
   same production client state and confirm the focused unit is inside the
   viewport before claiming pixels. Duplicate prose is never identity evidence.
5. **Autonomous edit drills use a named non-precious fixture.** Machine edits do
   not touch real material. Any proposed write to Sid's blocks is announced
   before it happens; his deliberate WAL is preserved after the wear.
6. **Input gates compare emitted keys with buffer delta.** Echo latency alone
   cannot see relieved events that never reach the buffer. The F4 falsifier is a
   headed long-block burst with exact emitted-versus-buffer accounting.
7. **Gate failure is a user-visible state transition.** Report the failure and
   pause closure immediately, then repair visibly. Never keep narrating PASS
   while a required surface or proof is red.

## Mechanisms that earned their keep

- Reusing the existing `:object/edit` request, journal, validation, graduation,
  revision, and read-unit overlay kept the package a connection rather than a
  parallel write architecture.
- Map-must-not-lie broke the Phase 0 tie when functional echo could not.
- The named narrowing seam let G7 preserve Rama truth without optimistic text.
- One focused falsification finder found the only HIGH and avoided redundant
  review fan-out.
- A synthetic real-runtime pre-drill gave the wearing a safe rehearsal without
  weakening it into a mock.
- Exact replay counts and same-unit reads replaced impressionistic restart proof.
