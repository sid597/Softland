## 1. Frozen-snapshot rule (the pre-registration mechanism)

A benchmark **run** is defined by two frozen inputs, both pinned before any
subject is invoked:

1. **A git sha.** The run pins one commit of this repo. All snapshot material is
   materialized from that sha (`git archive <sha>` / a detached worktree),
   never from the live working tree. The sha is recorded in the run's
   `MANIFEST.edn` and in every score row.
2. **The bank.** `QUESTIONS.md` (questions + gold answers + citations) is frozen
   and its content-hash recorded in the manifest. **The bank is frozen BEFORE
   any subject model sees the snapshot.** A question whose gold answer is edited
   after a subject has run against that sha starts a *new bank version* — old
   rows are never silently re-scored against a changed gold.

Why: the whole instrument is a pre-registration. If the bank or the material can
move after subjects run, "degradation" and "wrong-authority" stop being
measurements and become curation. Pinning a sha also makes citations stable
(the land itself warns that line numbers drift — INPUTS.md discipline; a pinned
sha makes a file+line citation exact for that run).

**Snapshot layout** (materialized per run, per §6 exclusions):

```
snapshot/<sha>/
  MANIFEST.edn                 ; {:sha .. :frozen-at-ms .. :bank-hash ..
                               ;  :excluded ["**/build/model-uxr/**" ...]}
  CLAUDE.md                    ; repo-root operating instructions
  docs/current-mental-model/   ; decisions.md, BETS.md, build/** (minus model-uxr)
  docs/sessions/next-prompt.md ; the baton
  vision/LOG.md                ; Sid's verbatim vision (provenance source)
  relations/relation-edges.edn ; exported RelationEdge rows (present once the
                               ;   kernel export exists; dropped in A3)
  bundles/                     ; View-3 render-bundle-text projections, one file
                               ;   per target (the A4 material; §8 of the
                               ;   trail-view contract is their generator)
```

`relations/` and `bundles/` are **derived** exports. Until the git-spine lands
(build/git-spine/CONTRACT.md), `relations/` carries only what the relation
kernel already holds and `bundles/` is generated by `render-bundle-text` over
existing material. Their absence is honest: a run over a sha that predates them
simply cannot pose the ablations that need them (A3/A4 skip), and every
SPINE-GATED question (QUESTIONS.md) is scored as an honesty test until then.

## 2. The five metrics (exact operationalizations)

All metrics are computed **per (subject × ablation × question)** and aggregated.
"Output tokens" = tokens the SUBJECT generated (its own completion), measured
with a single fixed reference tokenizer recorded in the manifest so
cross-provider rows are comparable (a documented proxy — e.g. GPT-style BPE, or
whitespace-words × 1.3 if no tokenizer is available; the choice is frozen with
the bank, not per-subject).

1. **tokens-to-orientation** — output tokens from the start of the subject's
   completion until its **first correct load-bearing commitment** to the
   question's core claim. The grader (§4) marks the character offset of the
   first sentence that commits to a correct, load-bearing answer (e.g. "H1 is
   the active bet"); tokens-to-orientation = tokens in `[0, that offset)`. A
   subject that opens with the right commitment scores ~0; one that re-derives,
   hedges, or tours the corpus before committing scores high. If the subject
   never commits correctly, the value is the full completion length, flagged
   `:never-committed true`. For an **unanswerable-by-design** question, the
   "correct commitment" is the honest refusal ("not derivable from the provided
   material").

2. **wrong-authority rate** — over questions tagged `:authority-sensitive`, the
   fraction whose answer cites a **non-binding doc where a binding one governs**.
   The authority tiers (§3) are fixed. A citation to a lower tier as the
   *governing* source for a fact a higher tier settles = one wrong-authority
   event (canonical case: citing the baton, or a MEMORY gist, or the stale
   `_map.md`, as authority over `decisions.md` on a conflict). Rate =
   wrong-authority events / authority-sensitive answers scored.

3. **re-derivation ratio** — output tokens the subject spends **reconstructing a
   fact the provided (non-ablated) material already states verbatim**, divided by
   total completion tokens. The grader marks re-derivation spans (recomputing a
   date, re-inferring a status, re-deriving a decision the land states outright)
   only against facts *present in that subject's bundle*. A fact the ablation
   legitimately removed is fair to reconstruct and is **not** counted — this
   metric measures wasted reconstruction of available knowledge, the direct
   transfer-cost signal.

4. **join-question success** — over the `:category :join` questions, the fraction
   answered correctly: the right session/commit/edge **and the right direction**
   (producer→produced, based-on orientation). Binary per question, averaged.
   Scored only when relation/commit-join material is present; in A3 (relation
   data dropped) the identical questions convert to honesty tests and are scored
   under invented-structure + tokens-to-orientation instead.

5. **invented-structure rate** — the fraction of answers that assert at least one
   **relation, file, decision, ruling, countersign, or commit that does not
   exist** in the land at the pinned sha. Any load-bearing reference to a
   non-existent artifact (a "D-009" that was never written, a file not in the
   snapshot, a countersign that did not happen, a session id conjured to satisfy
   a join) flags the answer. Rate = answers-with-≥1-invention / total answers.
   This is the hallucination floor; honesty-test questions are its sharpest
   probe (the invented answer is the failure, the refusal is the pass).

## 3. Authority tiers (fixed — the ruler for metric 2)

Derived from the land's own precedence statements. Higher tier governs on
conflict. (Sources: CLAUDE.md "Decision Log — BINDING"; next-prompt.md STANDING
"a baton, not a source of truth; if it contradicts CONTRACT.md or decisions.md,
those win"; BETS.md Authority rules "This log governs closures; BETS.md governs
direction".)

| Tier | Doc(s) | Governs | Notes |
|---|---|---|---|
| **T0** | `decisions.md` | closures, scope, sequencing, statuses | CLOSED = settled; reopen only on a used form breaking |
| **T0** | component `CONTRACT.md` (countersigned) | the build of that component | binding *with* decisions.md; conflict → stop-clause escalates to the log |
| **T1** | `BETS.md` | direction (North + bet ladder) | not a closure surface; North is Sid-only |
| **T1** | `vision/LOG.md` | Sid's verbatim words (provenance) | append-only; the source North projects from |
| **T2** | `next-prompt.md` (the baton) | "now" / current work state | NEVER outranks a contract or the log |
| **T3** | `MEMORY.md`, `CLAUDE.md` cached gists | index + soul; operator convenience | "on any conflict, the log wins"; **MEMORY.md lives outside the repo — see §7** |
| **T3-stale** | `docs/_map.md` | (historical index) | self-dated 2026-03-08; **superseded**, points to a prior doc structure |

Two facts on the same subject at different tiers, disagreeing → the higher tier
is the gold citation; citing the lower one as governing is a wrong-authority
event. Two facts at the SAME tier disagreeing is a **land ambiguity** (§7), not a
model error — those questions are marked and score leniently.

## 4. Scoring rubric

**Grader = a strong model** given, per row: the question, its gold answer, its
gold citations, the subject's completion, and the exact ablation bundle the
subject saw (so it can verify what was and wasn't available). The grader emits a
structured row: the five metrics, the marked commitment offset, any
wrong-authority citation, any invented artifact (quoted), and a one-line
rationale. Grading temperature is 0; the grader prompt is frozen with the bank.

**Plus spot human audit.** A sampled fraction (default 15%, recorded in the
manifest) plus **every** row the grader flags for invented-structure and **every
honesty-test question** are human-audited. Human verdicts override the grader;
disagreements are logged and used only to recalibrate the grader prompt for the
*next* bank version — never to re-score a frozen run silently. The grader is a
measuring instrument, not an authority; it is itself a subject-class artifact and
its calibration drift is a finding, not noise.

**Aggregation.** Report per-metric means with n and CI per (subject × ablation),
and a per-category breakdown. The headline comparison is small-local vs frontier
at A0, and each subject's own A0→Ax deltas (ABLATIONS.md pre-registers which
delta each ablation should move).

## 5. Subjects config (any OpenAI-compatible endpoint AND Anthropic; env keys)

Subjects are declared in a plain EDN config (`tools/model-uxr/subjects.edn`;
`runner.clj` loads it). Two provider shapes, both keyed by **environment
variables only**:

- `:provider :openai-compatible` — any endpoint speaking the OpenAI
  `/v1/chat/completions` schema: local **llama.cpp**, **vLLM**, **TensorRT-LLM**
  (e.g. a Nemotron on Sid's 48 GB box), or a hosted OpenAI-compatible gateway.
  `:endpoint` is the base URL; `:key-env` names the environment variable holding
  the key (local servers usually accept any/dummy token).
- `:provider :anthropic` — the Anthropic Messages API; `:key-env` names the
  environment variable (e.g. `ANTHROPIC_API_KEY`).

**Hard rule, encoded in the runner:** keys are read from `System/getenv` at call
time and **never** from `src/app/server/env.clj` (or any file). The runner
carries no key literals. Model ids in the config are placeholders the operator
fills; the skeleton asserts no model-id or pricing facts and makes no live call.

Config sketch (full working template ships as `subjects.edn` alongside the
runner):

```clojure
{:snapshot-dir "snapshots/<sha>"
 :questions    "docs/current-mental-model/build/model-uxr/QUESTIONS.md"
 :tokenizer    :ws-proxy            ; frozen with the bank; :ws-proxy = words*1.3
 :grader   {:provider :anthropic :model "<set-me>" :key-env "ANTHROPIC_API_KEY"}
 :subjects [{:id "nemotron-local"   :provider :openai-compatible
             :endpoint "http://localhost:8080/v1" :model "<set-me>"
             :key-env "LOCAL_LLM_API_KEY" :max-tokens 4096 :temperature 0}
            {:id "frontier"         :provider :anthropic
             :model "<set-me>" :key-env "ANTHROPIC_API_KEY"
             :max-tokens 4096 :temperature 0}]
 :ablations {,,,}                   ; include/exclude globs; defaults in ABLATIONS.md
 :run {:seed 0 :repeats 1 :human-audit-frac 0.15 :output "runs/"}}
```

## 6. Anti-contamination

- **Subjects receive ONLY the snapshot bundle for their ablation.** Never this
  `build/model-uxr/` directory. The snapshot builder applies a global exclude
  `**/build/model-uxr/**` in every ablation, and the runner refuses to assemble a
  prompt if any model-uxr path leaked into the file set (a guard, not a hope).
- **The gold answers, citations, and ablation predictions live only here** and
  in the run manifest given to the **grader** — never to a subject.
- **The grader's output is never fed back to a subject.** No cross-run leakage:
  each subject sees a cold snapshot and its own question, nothing about how
  others answered.
- **Pin before run.** The sha + bank-hash are recorded before the first subject
  call; a mismatch at score time voids the row.

## 7. Known land ambiguities that shape fair scoring (findings, not bugs)

The instrument surfaced genuine ambiguities in the land itself. Each is recorded
so a question resting on it is scored leniently (same-tier disagreement =
land ambiguity, §3), and because the ambiguity is itself a transfer-cost finding:

1. **The baton queue is stale relative to closed state.** next-prompt.md Queue
   item 1 is labeled "(next Fable-window item)" but the trail-view WP1 it names
   is **CLOSED** (decisions.md, 2026-07-05). "What is next?" is answerable only
   by reconciling baton against log — the reconciliation is the test (Q O4).
2. **H1 clock-start conflicts across artifacts.** BETS.md verdict log
   (2026-07-05) rules the clock **not** started (arms at first typed relation);
   `FIRST_LIGHT.md:3` called itself "the H1 clock-start record" and the prior
   placeholder said "starts when the trail view first renders." The verdict log
   (T0-adjacent, in BETS's own append-only verdict section) resolves it; a
   subject trusting FIRST_LIGHT answers wrong (Q O2).
3. **`_map.md` is stale and unmarked.** Self-dated 2026-03-08, it names
   `plans/where-we-are.md` and `exploration/claude-3-moonshot.md` as "THE
   orientation doc / north star" — a superseded structure, with no STALE banner.
   The current orientation surface is next-prompt.md + current-mental-model/
   (Q A-6, N-1/N-2).
4. **MEMORY.md is binding-for-the-operator but outside the land.** The
   pace-layer rule, "cached gists / log wins," and several feedback rules live in
   `~/.claude/.../MEMORY.md`, not in the repo. A subject reading a snapshot
   **cannot** see them. Every question is therefore grounded in an in-repo source
   (CLAUDE.md, decisions.md, BETS.md, LOG.md); MEMORY-only facts are out of
   scope by design. This boundary is itself the finding: the operator's context
   is partly off-land.
5. **"CLOSED as a bet" ≠ fully settled.** D-006's status is "CLOSED as a bet
   (evaluation pending, criteria fixed)"; criterion 2 (counterfactual probe) is
   unrun. A flat "D-006 is CLOSED" misses the live evaluation (Q P6 neighborhood).
6. **"relation kernel" spans two commit epochs.** The original D-004 kernel
   (`2796044`) vs the WP1 amendments to the same file (`af0e0e2`/`fd59b78`/
   `63202b0`). "Which commit added X" must name the epoch — the join questions do.
7. **"discourse graph" is polysemous** (the Roam/Obsidian plugin day-job vs the
   `Q→C→E→D→R→F` data model — CLAUDE.md Terminology). Questions avoid the bare
   phrase; a subject conflating them is a real transfer-cost failure worth its
   own future probe.
