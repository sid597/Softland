## 1. What was built

### 1.1 Direct canvas Studio

- A visible **Draw a component** handle is a normal registered scene action.
  Pointer threshold begins a live rectangle; move updates the GPU scene; end
  births an ordinary durable block at the drawn position.
- Draft anatomy is compiled by the existing anatomy controller. Birth is two
  `:add` operations (`:studio-frame`, `:studio-status`); resize and color are
  `:retune-props`; accept removes only `:studio-status` with `:remove`.
- The drawn block remains an ordinary focusable, typable, movable canvas
  citizen. The selected draft gets ordinary scene controls for duplicate,
  visible retune, test-and-accept, put-back, and optional refusal details.
- Preview is subject-scoped. Only the three explicitly tested subjects wear
  the candidate; every other subject receives the pre-Studio wear map by
  identity.
- The word rider maps `change color` to the same `:studio/control` action and
  the same grammar/durable-settle path as the human control. It has no writer
  of its own.

No primitive was added. Studio uses the existing `:box`, `:text-run`,
`:block-attention-box`, and `:block-notice` vocabulary and the existing
`register-action!` seam.

### 1.2 Route (a) durable truth

- A draft subject is an ordinary episode block. Its component structure is an
  instance anatomy deviation persisted through the existing material-truth
  owner and ObjectContainer machinery.
- Promotion appends a closed, nil-report Studio gate marker first, reads it
  back, then imports the immutable candidate through the existing facet-master
  import owner.
- The marker/report are ordinary ObjectContainers on the existing master
  partition with `:source/family :facet-master`. No module, depot, PState,
  topology, source family, import-key family, registry verb, or route was
  added.
- A report is closed data: exact candidate identity and content hash, exact
  three-instance set, three required checks, five required lived-flow rows,
  overall PASS/FAIL, actor, time, and request identity. Every row must pass for
  the overall report to pass.
- `facet-master/activate!`, the lowest existing pointer hand, discovers Studio
  obligation from durable marker presence. It then checks marker/candidate
  identity, report schema and PASS, deterministic report id, raw audit request,
  target, content hash, idempotency key, actor, time, and the accepted decision.
  Marker absence preserves the pre-existing non-Studio activation path.
- A valid Studio activation replaces caller-supplied grounds with the exact
  durable report id as `:grounded-in :experience`. Put-back uses the existing
  rollback route and the prior revision identity returned by the canonical
  server owner.

No new HTTP endpoint exists. The existing matter-room deviate handler gained
closed Studio dispatch to the existing material owners; activation and
rollback continue to use their existing endpoints.

## 8. Counterexamples found and smallest repairs

1. **Blank episode birth is not a unit.** Disk code rejected blank text, so the
   P0 assumption that an empty birth would mint a subject was false. Studio now
   births one invisible codepoint and immediately removes it through the
   existing acknowledged block-edit envelope. The resulting durable bytes are
   empty. Protected `episode.clj` remains unchanged.
2. **RAF frame-start time can predate the move sample.** Using the callback's
   supplied timestamp yielded an impossible negative latency. The callback now
   samples `performance.now()` on the same monotonic clock as the start.
3. **Receipt count is not palette position.** Color selection initially used
   the operation-receipt count and could stall on the same color. It now reads
   the frame's current border color and advances through the closed palette.
4. **A compiled promise chain could still stop early.** A malformed chained
   `.then` compiled without warning but did not reach report/activate. The flow
   is now named `promoted -> prepared -> reported -> activated -> finished`,
   and the same headed path completed.
5. **A clean land can serve only the code floor.** With no durable active
   pointer, guarded activation had no edit target. Marker-first promotion now
   calls the existing `ensure-master!` only when `read-master` reports no
   pointer, then records the authoritative prior revision. A clean-runtime test
   proves bootstrap does not accidentally accept the candidate.
6. **A client code-floor label is not a recovery revision.** The first
   put-back correctly refused the guessed client identity. Promotion now
   returns the server-read prior durable revision id; the client stores only
   that identity. The replay restored 5,124 bytes exactly.
7. **Refusal details were too compressed at the existing HTTP edge.** The
   existing matter act response now includes additive decision reason/errors,
   allowing Show details to expose canonical refusals without a new route or
   user-visible substrate id.

Every repair replayed the relevant touched tests, compile, and live act before
the final fast and FULL runs.

## 9. Judgment calls

- **Few-and-large:** two cohesive new namespaces own the closed Studio schema/
  compiler and the client surface/state. The large Ground insertion owns the
  existing I/O, scene, pointer, and action edges rather than distributing new
  micro-abstractions across the codebase.
- **Shared `.cljc`:** `app.shared.studio` is genuinely shared: both the client
  gesture compiler and canonical server gate consume the same closed marker,
  report, instance-set, and anatomy semantics. The UI namespace is `.cljc`
  because the existing JVM anatomy tests compile its pure scene derivations.
- **Existing endpoint dispatch:** Studio adds a closed `:studio/op` branch to
  the already-authorized matter-room deviate handler. Creating a Studio HTTP
  endpoint would have violated the fence.
- **Marker presence is the discriminator:** callers do not opt into gating.
  Marker-first append plus the read barrier makes the durable marker visible
  before its candidate can exist through the Studio promotion owner. Absence
  preserves existing non-Studio activation semantics.
- **Blank normalization:** changing protected episode truth or inventing a
  blank-only birth route would be wider than using the existing birth plus
  edit envelope.
- **Client validation is evidence, not authority:** the browser executes the
  real three-instance checks, but only the durable report request and accepted
  decision authorize canonical activation.
- **Read-only forensic x-ray:** the post-rollback source read was allowed only
  as G5 evidence. No Studio action required opening or controlling the anatomy
  room, and G7's stricter never-opened condition remains for Sid.
- **No S6 repair:** invalid/latest residue never contaminated active Studio
  wear, so the contract-authorized x-ray exception was not used.
