● OK, here's the Electric/Missionary way to think about this:

  ★ Insight ─────────────────────────────────────
  The Missionary Principle: computation should be proportional to change.

  In a reactive DAG, each node should only recompute when its own inputs change.
   m/latest is the combinator that says "recompute when ANY input changes." So
  one m/latest with 25 watched atoms = "recompute everything when anything
  changes." That's not a reactive graph — that's a polling loop with extra
  steps.

  The problem in Missionary terms: You have a star topology (every computation
  depends on every atom) when you need a tree topology (each branch depends only
   on its own atoms).
  ─────────────────────────────────────────────────

  The Current Shape (the problem)

  !caret-visible ──┐
  !shimmer-phase ──┤
  !flow-state ─────┤
  !scroll-y ───────┤
  !drag-state ─────┤        ┌──────────────────┐
  !hovered-row ────┼───────▶│  ONE m/latest     │──▶ rects
  !editor-doc ─────┤        │  (fn [25 args]    │
  !chat-input ─────┤        │    (cond ...))    │
  !detail-scroll ──┤        └──────────────────┘
  ... 16 more ─────┘

  Every atom change fires the entire function. Caret blinks → ticket list
  rebuilds. Chat input changes → editor rects rebuild. Everything causes
  everything.

  The Electric Way (the solution)

  Split into scoped flows — each m/latest watches only what its code path
  actually uses. Then compose them:

  ;; Step 1: A tiny flow that determines which MODE we're in
  (def <mode
    (m/latest
      (fn [flow-state current-file extract-preview]
        (cond
          (:rt-node extract-preview)         :extract-preview
          (flow-canvas-active? flow-state)   (if (= :intake (:node flow-state))
  :intake :run)
          (some? current-file)               :file-open
          :else                              :editor))
      (m/watch !flow-state)
      (m/watch !current-file)
      (m/watch !extract-preview)))

  ;; Step 2: Each branch watches ONLY its own atoms
  (def <editor-rects    ;; watches: !editor-doc, !caret-visible, !focus, 
  !fold-data ...
    (m/latest (fn [doc caret fold ...] (compute-editor-rects ...))
      (m/watch !editor-doc) (m/watch !caret-visible) ...))

  (def <intake-rects    ;; watches: !flow-state, !scroll-y, !detail-scroll-y, 
  !drag-state ...
    (m/latest (fn [flow scroll-y detail-sy ...] (compute-ticket-list-rects ...))
      (m/watch !flow-state) (m/watch !scroll-y) (m/watch !detail-scroll-y) ...))

  (def <file-rects      ;; watches: !editor-doc, !caret-visible, !agent-output, 
  !chat-scroll-y ...
    (m/latest (fn [doc caret agent-output ...] (compute-3-pane-rects ...))
      (m/watch !editor-doc) (m/watch !caret-visible) ...))

  ;; Step 3: Outer m/latest picks the right branch
  (def <final-rects
    (m/latest
      (fn [mode editor intake file-open sidebar]
        (let [content (case mode
                        :editor          editor
                        :intake          intake
                        :file-open       file-open
                        ...)]
          {:rects (into (:rects sidebar) (:rects content))
           :shadows (into (:shadows sidebar) (:shadows content))}))
      <mode <editor-rects <intake-rects <file-rects <sidebar-rects))

                                    ┌─ <editor-rects ◀── !caret, !doc, !focus
                                    │
  !flow-state ──▶ <mode ──▶ select ─┼─ <intake-rects ◀── !flow-state, !scroll-y,
   !drag
                                    │
                                    └─ <file-rects   ◀── !doc, !caret,
  !chat-scroll

  ★ Insight ─────────────────────────────────────
  Why this fixes the problem:
  - Caret blinks → only <editor-rects and <file-rects recompute (they use
  !caret-visible). <intake-rects doesn't watch it, so it does zero work.
  - !detail-scroll-y changes → only <intake-rects recomputes. Editor cursor
  stays untouched.
  - The unused branches still compute (Missionary is eager), but they're cheap
  because their inputs haven't changed, so m/latest doesn't fire them.

  The deeper principle: In Missionary, the flow graph IS your architecture. A
  flat m/latest is a monolith. Composed m/latest blocks are microservices. Each
  one has a clear responsibility and a minimal dependency set.

  One caveat: The unused branches (e.g., <editor-rects when in intake mode)
  still run and hold memory. If that matters, you can use m/cp + m/?< to
  conditionally subscribe — but that adds complexity and you'd need to be
  careful about the cancellation patterns from CLAUDE.md.
  ─────────────────────────────────────────────────

  Want me to implement this refactor on <editor-rects? The same pattern applies
  to <combined-text-ops which has the same 25-atom star shape.

  notifies watchers, even when the new value equals the old value. m/watch uses
  add-watch under the hood, so every reset! produces a new emission in the flow.
   This triggers m/latest → new rect objects → new world snapshot → GPU
  re-render, 60 times per second. The sidebar already had the guard (when (not= 
  new-id ...)); the flow canvas was missing it.

  The pattern to follow: Any reset! or swap! that feeds into a m/watch should be
   guarded with a change check: (when (not= new-val @!atom) (reset! !atom 
  new-val)). This is the reactive equivalent of shouldComponentUpdate in React.

● I think I found the deeper issue. Let me trace through what happens when the
  caret blinks while in intake mode:

  1. !caret-visible toggles → <editor-content recomputes (it watches
  !caret-visible)
  2. Combiner fires (one of its inputs changed)
  3. content = (case :intake intake) — picks the unchanged intake result
  4. BUT: the combiner allocates a new {:rects (into ...) :shadows (into ...)}
  map every time
  5. <world-snapshot sees a new object → identical? fails → GPU re-renders
  6. Every 530ms, the GPU re-draws the entire frame even though nothing visual
  changed

  This means hover rects get re-uploaded to the GPU 4x/sec (caret + shimmer).
  The re-draw could cause a single-frame flash between clear and draw.

  The fix: cache the combiner output so it returns the same object when the
  selected content hasn't actually changed.
