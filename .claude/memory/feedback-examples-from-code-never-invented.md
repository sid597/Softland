Examples come from the code as it is or from Sid's own words, never from an
invented product scenario. If a use case does not exist in the tree, say
"no case exists yet" and stop.

**Why:** Sid reads an example as a statement of what the thing does. Two
invented examples ("a scrolling note", "a ghosted group") in the 2026-09-03
deletion sort made him ask "why do we even have a scrolling ... are the
examples like made up or existing code if they are code they certainly should
not be here". The example imported a product idea Softland does not have and
cost him the decision.

**How to apply:** For a function, give input, output, and the caller that
exists; if none exists, say so. For a meta thing, give two examples drawn from
the tree or from `vision/LOG.md`, each anchored. Composes with
[[feedback-explanations-simple-story-first]] and
[[feedback-lived-walkthrough-design]].
