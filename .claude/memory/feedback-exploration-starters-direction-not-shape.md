**Why:** A prompt is an anchor and so is a board block — any packaging
of an unexplored thing pre-structures the exploration and drags the
next session down to the packaging's level. Tombstones ("deleted at his
word", "this line supersedes…") are instruction-shaped absences a
future agent must parse; the settled-ground law already said it:
living docs carry current state only, plain language, git keeps
history. The deeper failure: automating guidance of HIS explorations —
the machinery (banks, starters, capture offers) inserted itself where
only his intent belongs.

**How to apply:** When something is an exploration, it gets NOTHING on
disk — no board bank, no starter, no LOG-capture offer, no register
instructions — unless Sid asks. He opens it fresh at his own hand; the
agent's whole job there is thinking with him in the chat. When
deleting or amending living docs, leave current state only — never a
trace of what was deleted or why. Contract-shaped starters are only
for work whose plan is already validated. Related:
[[logistics-answers-are-artifacts]], [[meta-failure-generators]].
