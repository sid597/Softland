When Sid opens a waist-line sort of a code area, the division of labour is fixed: opus
subagents are the hunter-gatherers (one per disjoint slice, facts only, tagged
checked/derived/assumed, no verdicts), and the session model does the sensemaking —
the above/waist/below story, the custody-vs-scene-memory sort, the forks. The docs
corpus stays closed for that session; the map comes from code (comments/docstrings
inside source are fine and are where the "why" lines come from) plus a mechanical
require graph for reachability.

**Why:** his 2026-08-26 handoff, verbatim: "Use opus as your hunter-gatherer. You do
the forest / sensemaking / decision-guiding, not the grunt work. Do not read the docs —
they will degrade you. Talk to me the simple way: what is above the waist, what is the
waist, what is below — AS OF TODAY, from the code. Then one notch down. No zoom ladders.
Nothing lands on disk until I say so. Think with me first."

**How to apply:** (1) build the require graph + reachability from the real entry points
first (it framed everything: two islands, no wire, draw-frame! dead); (2) dispatch
hunters with one shared brief and disjoint file lists; (3) sort by his two-second test,
marking positions as POSITION and keep/cut verdicts withheld; (4) chat = ≤15 plain
numbered sentences + tiny one-idea diagrams, the picture = one SVG at one grain in a
scratchpad artifact, never a repo write. Companions: [[feedback-code-maps-one-notch-in-out-why]],
[[feedback-explanations-simple-story-first]], [[feedback-corpus-terms-never-back-at-sid]].
