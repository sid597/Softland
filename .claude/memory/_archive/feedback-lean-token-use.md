During the fabel-design session (2026-06-10), Sid stopped a running deep-research
workflow twice: first to cut the 3-vote adversarial verification phase ("it will
take too much tokens"), then rejected the resume entirely: "i don't want to use
so many tokens for tasks that are just like good to have and like defensive
types."

**Why:** Sid is a solo founder paying for tokens. Verification passes, judge
panels, and multi-agent fan-outs are "good to have" insurance, not value — the
value is the synthesis. He'd rather have Claude's direct judgment over raw
material than pay 3x for adversarial confidence.

**How to apply:**
- Default to direct inline work (own searches, own synthesis); no subagent
  fan-out unless he asks or the task truly can't fit one context.
- When he asks for something heavyweight (deep research, workflows), use the
  minimum phases that produce the deliverable; name what was skipped in one line.
- If a heavy process gets interrupted, SALVAGE what already ran (transcripts,
  partial outputs on disk) instead of rerunning — paid-for tokens are sunk value.
- Defensive layers (adversarial verify, N-vote panels) only on explicit request
  or for irreversible/high-stakes claims.
- CRITICAL NUANCE (learned the hard way same session): lean applies to PROCESS,
  not to the DELIVERABLE. Sid was unimpressed by a 200-line compressed synthesis
  of a 20-source corpus ("i was hoping deep and diverse and more navigatable").
  Research syntheses should be deep, quote-bearing, and navigable — he suggested
  HTML and the self-contained HTML report (sticky nav, evidence cards with
  confidence badges, counter-evidence sections, filterable claim+quote appendix
  generated by script from transcripts) landed well as a format. Generate bulk
  content (appendices) by script from on-disk data; spend hand-written tokens on
  synthesis quality.
