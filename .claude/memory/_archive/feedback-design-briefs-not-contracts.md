2026-07-06, UI design pass (sitting 3): Fable wrote executor prompts for the
claude.ai design harness as engineering contracts — numbered hard constraints,
tier tags, gate-style checks, data dumps. Sid corrected: "the design harness …
might work best with how a designer would understand … you give it exploration
direction .. what will be there in that scene … what you have is like this
because it's being written in claude code and that is eng focused."

**Why:** a design harness has no repo access and no canon; it responds to
scene, mood, cast, composition, and named freedom-to-explore. Contract format
produces compliance, not craft. Also: Sid decomposes by design layers and
wants the TOP layer (world look) alone first — deeper layers (grammar
close-up, container spec) only for the survivor his eye picks.

**Second correction, same sitting (harder):** v2's briefs led with mood and
framed System 1 as "Sid's wall made alive" (kraft paper, warm ink). Sid killed
it on sight: "the goal of code is not to make a reality emulator … what is the
current trail-view problem?" The wall/notebook/terminal are provenance of the
QUESTIONS the view answers (where are we / how did we get here / which
crossroads) — never a material target. A brief that doesn't state the problem
is a mood board.

**Third correction (2026-07-10, chat-to-blocks round, hardest):** v3 opened
with the problem but wrapped everything in the project's internal metaphor
register ("the river", "debris", "a lived night", MOOD sections, "a place
you inhabit"). Sid, furious: "wtf is this river sediment shit … just put
the fucking effort into the exact problem that i described in a design task
language." Scene/mood/cast was MY literary instantiation, not his ask — his
2026-07-06 correction wanted content-inventory + exploration direction, not
world-poetry. Internal codenames must never cross the boundary: a brief is
an API between contexts and its vocabulary must be the receiver's. The
format that survived all three corrections is a designer's work ticket:
Context (plain product terms) → The task → The structure it must express
(user's own words) → Explorations wanted (named directions + invent-one) →
Design questions each must answer → Data → Constraints (incl. one-line
visual tone). No MOOD/SCENE/CAST headers, no metaphors, no narrative.

**How to apply:** when packaging design work for an external render session:
(1) every brief OPENS with THE PROBLEM (the user's situation + how the current
screen fails him) and THE SCREEN'S JOB, then THIS SYSTEM'S BET — each visual
system argued as a distinct bet against that problem; (2) then scene / boards
as named moments / manners (canon compressed to ~6 values, never cited) /
EXPLORE section naming where imagination is wanted / verbatim real material /
deliverable; (3) one brief = one paste = one fresh chat (fresh-cut rule);
(4) tier/feasibility tags stay Fable-side, never in the brief; (5) top layer
first, iterate by talking to the render's chat naturally; (6) never emulate
the artifact being replaced (taste #17).
