Sid, 2026-09-07, handing REFUTE-1 to the design session: "USE YOUR JUDGMENT TO FOLD THESE IN CODEX CAN BE VERY pushy about what it says needs to be done .. for anything related to naming things decide but at the end give the list of decisions made around it", and, as a suggestion, "use the subagents to purely purely do a read of full file or gather data becasue on huge files there needs to be some chunking and we don't want that to end up on fable-max context".

**Why:** a refutation with executed receipts is right about what it measured and pushy about what must follow; each finding still splits want-vs-is ([[feedback-normative-artifacts-protect-the-want]]), and the repair is the design chair's, not the refuter's. Naming is the chair's to settle so the literal landing never has to choose ([[feedback-fable-shortcuts-codex-literal]]); the list at the end lets Sid veto a name in one line. The artifact under repair is read whole by the chair; every other file is a gatherer's read returning anchors.

**How to apply:** default for any fold of a review into a design: read the design whole, spot-check the decision-changing receipts through one read-only gatherer with a scoped file list, then compose the whole repair as one write and one commit; where the refuter offers options, take a position with its exit rather than carrying the options; where it demands scope (a new operation, a completed protocol), narrow the claim or name the candidate unless a production record needs it now; close with the numbered list of naming decisions and the items that are Sid's. The departure is a finding that is itself a ruling of Sid's, which is asked back once ([[feedback-rulings-quote-sid-verbatim]]).
