**Dead means wrong form, not uncalled.** Sid (2026-09-02, the waist round two): "Things that should be dead are not explicitly... that are not being called from anywhere, but like that exists for some future valid case and are implemented in the form that they should be." Something uncalled that exists for a valid future case in the form it should have is alive. Something called every frame whose form is wrong for the waist is dead. And the order is: remove now, never "keep it until a better one comes."

**Why:** a grep-reachability delete list (which I produced first) keeps costume code that is exercised by the harness (a process-local admission stamp, a GPU slot on every op, a receipts ledger inside a painter) and deletes seeds of valid future capability (pixel readback for agents' eyes). His criterion sorts by form against the target architecture, so a template cut on one kind repeats cleanly on the others.

**How to apply:** before any delete list, state the target form of each piece (input shape, output shape, who decides each), then judge form, not call count. Say "uncalled" only as a fact, never as a verdict. A replace-in-one-move (grammar, stroker) is a valid "remove now" when nothing else says what the thing is.
