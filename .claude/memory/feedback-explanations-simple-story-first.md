When Sid asks to *understand* the system (status, architecture, "explain it to
me"), the deliverable is a SHORT STORY IN PLAIN WORDS, never a reference
document. Three escalating "comprehensive" writeups (2026-08-13/14: the three
parallel essays, the rosetta message, one-block-two-lives) each left him more
lost — final verdict: "unreadable… braindead reading it, not able to understand
shit."

**Why:** density reads to him as noise, not rigor. Tables, layer taxonomies,
minted vocabulary, file:line receipts, epistemic marks, and 20-line annotated
ASCII walls each cost comprehension; stacked, they cost all of it. He is a
visual learner — but a dense ASCII diagram is not visual, it is code.

**How to apply:**
- Core story ≤ ~15 numbered sentences, everyday words (database, server,
  browser, block, editor), zero code names on first pass.
- Diagrams ≤ 8 lines, ONE idea each, generous whitespace.
- Number the points so he can poke one; expand ONLY the piece he names, in the
  same plain style. Depth on demand, never up front.
- Receipts/field names live in a later pass or on request — precision is not
  abandoned, it is deferred.
- Composes with [[feedback-guides-integrate-never-accrete]] and
  [[feedback-preserve-sids-vocabulary]]; second push on one topic = frame is
  wrong, re-derive from the root ([[meta-failure-generators]]).
